# Proxus register maps: parity pass and comparison

[proxus-io/modbus-register-maps](https://github.com/proxus-io/modbus-register-maps)
publishes 64 device files from 12 vendors, with 20,545 registers in all. This
page records how the corpus was brought on par with it, what the cross-check
found, and how the two approaches compare. Nothing here changes the draft, the
schema or the corpus rules. The proposals at the end are for the maintainer to
accept or reject.

## Method

- Every Proxus device file was inventoried, and every device not yet in the
  corpus was mapped under the existing rules. A contract is generated by an
  extractor from a checksum-pinned document on the vendor's own host. Each
  convention the mapping depends on is handled by policy rules 1 to 4 (see
  [corpus/README.md](../../corpus/README.md)).
- A Proxus map is never a source or evidence. Its sources were used as leads,
  and its registers as a second transcription to compare with. The vendor
  document decides every difference.
- Conventions that a Proxus file takes from a third party (an open-source
  driver, a client default, another device by analogy) count as unstated
  (rule 4).

## Cross-check

- **Compared:** 818 contract points with the Proxus register at the same table
  and address.
- **Outcome:** 478 equal. 70 sit in the other 16-bit table, where Proxus uses
  holding registers and the vendor allows both function codes. 139 are not in
  the Proxus file. 131 differ.
- **The differences are not errors:**
  - 122 are Fronius points. Our contracts read the integer-and-scale-factor
    SunSpec layout and Proxus the float layout, so the same address holds a
    different point.
  - 5 are the meter clock: we read the year register, Proxus the whole
    4-register date-time block as raw.
  - 2 are the ATV61 and ATV71 motor current. Proxus gives no unit or scale and
    refers to the manual, which states 0.1 A.
  - 2 are a unit spelling (`N.m` against `Nm`).
- **Our contracts:** no difference led to an error in them.
- **Whole-file checks:** beyond the contract points, the groups compared every
  register of most Proxus files with the vendor rows. The transcriptions are
  faithful:
  - Fronius: 1,451 of 1,451 rows equal.
  - Schneider meters: 5,061 of 5,088 equal.
  - ION: 807, 809 and 845 registers equal the workbook at register minus one.
  - ABB meters (515 registers), Carlo Gavazzi (about 270), Siemens (764),
    Janitza and Lovato: no address, width or scale error.

Errors found in the Proxus files. They are recorded in the parity reports, and
none was reported upstream.

| File | Finding |
|---|---|
| ATV340, ATV600, ATV900 | 186 parameters the workbook types "UINT (Unsigned32)" or "INT (Signed32)" are typed 16-bit (the importer reads the first word of the cell). |
| ATV61 | SMAL and SMIL swapped, inherited from the vendor workbook; the manual has them the other way round. |
| ACS580, ACS880 | Five readouts per drive carry a unit and no scale; the manual scales them to another parameter (20000 = the value of 46.01, and so on). The note says so; the structured fields do not. |
| Fronius (all) | The importer drops the "Range of values" column: enumeration values, bit names and "not supported" marks (44 to 59 registers per file). |
| iEM3000 | Hand-transcribed from a printed edition, which carries an outdated unit and contradicts the file's address offset. |
| UMG 103-CBM and five other Janitza files | The stated reason for the address base ("lists number from register 0 and give no example frame") is wrong for two lists, and four of the six manuals give an example frame. |
| PAC3200, PAC4200 | Vendor errata copied without a note: a power factor with unit var (both), and two of three reactive-power rows named L1 (PAC4200). |
| SDM72D-M | Mapped with ABCD word order by tool default, although the file's own note says the order is not stated. |

## How the approaches differ

| | OpenModbus corpus | Proxus |
|---|---|---|
| What is published | A read-only subset per model (about 15 to 20 points), generated from the vendor document | The whole register list per device family (73 to 1,911 registers), including writable settings |
| How it is produced | One extractor per source; `require()` fails the build when the document changes or a row is unexpected | Importers for vendor workbooks (Schneider, Fronius); hand transcription for PDFs |
| Source | A direct HTTPS download on the vendor's host, pinned by SHA-256 in the lock and re-fetched by CI | Any HTTPS link, including reseller copies. The SHA-256 is recorded, but the URL is often a landing page that does not return the pinned bytes (ABB library, Siemens support, se.com FAQ pages) |
| Conventions | Rules 1 to 4. A companion document is pinned as evidence and the extractor checks the statement in its bytes. A forced reading needs a maintainer item | Free-text notes with a reason, one sentence per convention. Missing word order defaults to ABCD. Conventions carried over from other devices or third-party drivers |
| Semantics | UCUM units, exact-decimal conversion, scale-factor references, `invalid` sentinels, enums and flags, read constraints | Free-text units (90 spellings), `scale`/`scale_factor`, value lists, notes |
| Verification status | `verification: documented` per contract | Levels L1 to L3 from hardware reports filed through an issue bot and tied to the map's content hash. None was recorded at the time of this pass |
| Per-model scope | One contract per model; the extractor selector applies the model's differences | One file per family; `applies_to` per register |
| Licence | MIT for everything (D15) | CC BY 4.0 for maps, Apache-2.0 for tools, with a takedown process |

What Proxus does better:
- **Breadth.** It holds whole register lists.
- **Hardware-verification workflow.** Reports are tied to a content hash.
- **Per-row notes.** It records vendor slips and doubts on the row itself.

Its weak spots are the ones our rules exist for:
- **Pins.** Many cannot be re-checked from their URL.
- **Unstated conventions.** They become silent defaults.
- **Type errors.** Typing from a partial cell turned 32-bit values into 16-bit
  ones.
- **Free-text meaning.** Meaning that lives only in a note (scales to other
  parameters, configuration-dependent resolution) misleads any reader that uses
  the structured fields.

## Proposals

None of these is implemented. The first five are tooling and process; the rest
touch the draft and need the maintainer.

1. **Row dump for cross-checks.** A `run.py` option to write every row an
   extractor parses, not only the selected points, to a scratch file. Comparing
   whole lists with a second transcription, as in this pass, then needs no
   one-off scripts.
2. **Rule-3 marker in the contract.** `run.py` writes
   `x-otfabric-corpus-inferred: [work item IDs]` into `info` when a contract
   rests on a forced reading. Consumers can then filter on it without reading
   the description. This is an `x-` key under D12, so it needs no schema change.
3. **ZIP member pins.** For archive sources the lock records the member's
   SHA-256 as well as the archive's, so the health check can say which part
   changed. Proxus does this for the ION9000 archive.
4. **Vendor permalinks as a second `download_urls` entry**, where a vendor
   offers a stable redirect (as `fronius-primo-sunspec-maps` already does).
5. **Source-discovery notes.** Record the direct-download patterns found in
   this pass:
   - ABB `search.abb.com/library/Download.aspx`;
   - se.com `downloadUrl` and JSON-LD attachments;
   - Janitza `/downloads` pages;
   - Siemens `cache.industry.siemens.com`;
   - Eastron's European site.
6. **Device-verification reports (D14 level 4).** A report format tied to the
   contract's content hash, adapted from Proxus's L1 to L3. It would let a
   contract move beyond `verification: documented`.
7. **Kept rows with a vendor-erratum note.** Today a row with a vendor slip is
   dropped and gets a work item. Keeping the row with a description of the slip
   serves integrators better, but it means publishing a corrected value. This is
   a policy decision.
8. **Optional comparison job.** A non-blocking corpus-health step could compare
   contracts with the Proxus file where both pin the same document hash, and
   open work items on differences. Their maps stay out of the evidence chain.
   This adds a third-party dependency.

## Not adopted

- Landing-page URLs, reseller copies and analogy-based conventions: the reasons
  are in the table above.
- Whole lists with writable registers: the corpus stays read-only until D11 is
  settled.
- A default word order: D5 requires the order in `defaults` or per point.
